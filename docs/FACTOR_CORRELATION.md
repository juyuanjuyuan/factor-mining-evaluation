# 因子库相关性矩阵

正式因子库的相关性控制独立于单因子 IC/分组收益评价。因子定义仍只保存在
`factor_registry/`；矩阵和因子暴露缓存保存在 Web 平台状态目录：

```text
outputs/webapp/factor_correlation/
├── matrix.csv
├── metadata.json
└── exposures/
```

`matrix.csv` 是当前正式因子库的完整 `n × n` Pearson 相关性矩阵。每个元素由两
个因子在所有对齐、有限的 `(交易日, 证券)` 联合观测值上做 pooled Pearson
correlation 得到；这不是原始协方差。相关系数才有可解释的统一阈值，因此提交
规则是所有**非对角元素的绝对值**均不大于 `0.75`。对角线是因子与自身的相关性，
恒为 `1`，不参与阈值判断。

从测试库提交候选因子时，服务会：

1. 检查缓存的定义哈希与输入数据文件签名；缓存失效时重建现有库矩阵；
2. 仅计算候选因子的因子暴露，并读取已有因子的缓存暴露；
3. 只补算候选因子对已有 `n - 1` 个因子的相关性，构成新的行和列；
4. 若任一新旧因子对的绝对相关性超过 `0.75`，以 422 拒绝提交并保持旧矩阵；
5. 注册表写入成功后，原子保存新的矩阵和候选因子暴露缓存。

若底层行情文件或正式库的因子表达式发生变化，缓存会自动失效并全量重建，以避免
用不同数据版本的因子暴露拼接矩阵。`/factors` 通过 `/api/factor-correlation` 展示
该矩阵、最大非对角绝对相关性与超阈值因子对。

## 两因子分段相关性

全样本矩阵仍作为正式因子库的总览和提交门禁。点击任一非对角矩阵值时，前端调用
`/api/factor-correlation/pair?factor_a=...&factor_b=...`，服务复用已经过数据签名
校验的暴露缓存，按日期顺序切成 60 个交易日的非重叠窗口：

```text
[t1, ..., t60], [t61, ..., t120], ...
```

每个完整窗口继续使用 pooled Pearson 口径；尾部不足 60 个交易日的部分不纳入。
窗口表保留有符号相关系数，但“最大分段绝对相关性”和“超过阈值的窗口数量”均按
`abs(correlation)` 计算，只有 `abs(correlation) > 0.75` 才视为超过阈值。分段结果
用于诊断相关性随时间的变化，不改变现有全样本相关性入库门禁。
